# گزارش آمادگی انتشار PerPix v1 — ۱۷ اکتبر ۲۰۲۶

وضعیت سند: **گزارش نهایی بررسی محلی؛ مجوز انتشار نیست**. اجرای کامل تاریخی Playwright از ۴۸۶ آزمون با **۴۲۳ PASS، ۲۰ FAIL، ۷ SKIP و ۳۶ اجرا‌نشده** در ۳۸٫۱ دقیقه پایان یافت. دور ۱۱۶ آزمون پس از اصلاح اولیه harness نیز با **۷۱ PASS، ۹ FAIL، ۲ SKIP و ۳۴ اجرا‌نشده** در ۱۰٫۹ دقیقه و exit 1 واقعی پایان یافت؛ این تاریخچه حفظ شده است.

پس از AUTH-03 هر **۱۸ آزمون احراز هویت/پروفایل PASS** شدند. اصلاحات بعدی Home و Studio در اجراهای جداگانه شاهد GREEN دارند؛ دور نهایی Studio برابر **۳۶/۳۶ PASS با exit 0** است و همراه موارد قبلی هر ۶۸ مورد فایل را پوشش می‌دهد، اما اجرای واحد کامل روی آخرین ویرایش ثبت نشده است. **سه شکست WebKit در wallet/checkout با علت اثبات‌نشده باقی مانده‌اند.** آخرین build، lint عمومی و به‌روزرسانی graphify با exit 0 تکمیل شدند؛ production preview محلی نیز **۱۰/۱۰ PASS در ۱٫۳ دقیقه، با exit 0 واقعی** دارد.

## ۱. تصمیم انتشار

**NOT READY.** اصلاحات احراز هویت، cache پروفایل، بازیابی route، تولید محتوا و بارگذاری تصویر شواهد GREEN هدفمند دارند. اجرای کامل تاریخی با ۲۰ شکست و اجرای مجدد هدفمند پس از اصلاح اولیه harness با ۹ شکست پایان یافته‌اند؛ اصلاحات بعدی Home و Studio شواهد GREEN در اجراهای جداگانه دارند، اما سه شکست WebKit در wallet/checkout با علت اثبات‌نشده باقی مانده‌اند. نقص تازه AUTH-03، بازگردانی cache یک حساب در session دارای token دیگر، در Chromium بازتولید و سپس اصلاح شد؛ چهار آزمون session cache در Chromium/WebKit و مجموع ۱۸ آزمون احراز هویت/پروفایل GREEN هستند. production preview محلی با mock، ۱۰/۱۰ PASS است؛ محیط واقعی staging/backend، پرداخت، object storage، چرخه PWA و مسیرهای حیاتی واقعی برای صدور تأیید انتشار بررسی نشده‌اند.

این تصمیم به معنای اثبات خرابی در تمام مسیرهای بررسی‌نشده نیست. موفقیت آزمون‌های دارای mock نیز به‌تنهایی صحت سرویس‌های واقعی، پیکربندی محیط انتشار یا تسویه پرداخت را ثابت نمی‌کند. هیچ deployment، merge، push، tag، تغییر نسخه یا پرداخت واقعی انجام نشده است.

شدت‌ها در این سند: **P1** شکست مسیر اصلی یا مانع عمده انتشار؛ **P2** نقص معنادار در عملکرد یا استفاده؛ **P3** نقص یا بهبود با دامنه محدود. منشأ نقص، زمان وجود آن نسبت به base است و با شدت آن تفاوت دارد.

## ۴. موارد باقی‌مانده و مرز تأیید

### الف) موارد قطعی باقی‌مانده

AUTH-03 یک نقص قطعی جداسازی session بود که پس از اصلاح، چهار آزمون session cache در دو موتور و مجموع ۱۸ آزمون احراز هویت/پروفایل آن GREEN شده‌اند؛ این شاهد محدود به سناریوهای مرورگری mock است. اجرای کامل تاریخی ۲۰ شکست ثبت‌شده دارد و اجرای مجدد هدفمند ۱۱۶ آزمون نیز ۹ شکست و ۳۴ مورد مسدود ثبت کرده است؛ جزئیات هر دو اجرا در بخش ۵ تفکیک شده‌اند. شکست wallet و دو حالت payment در WebKit **حل‌نشده** هستند؛ شکست آزمون قطعی است، اما علت محصول، harness یا محیط اثبات نشده است. تکرار بیشتر این موارد بدون شاهد تازه برنامه‌ریزی نشده و از صرف timeout، patch محصول استنتاج نشده است. دو شکست تاریخی dynamic config از نبود fixture در repository مجاور backend هستند و تا فراهم‌شدن همان ورودی معتبر، پوشش آن دو مورد تأیید نشده است.

محدودیت قطعی fault injection در AUTH-02: وقتی IndexedDB/persister حذف را رد کند، حذف فیزیکی داده persisted تضمین نمی‌شود؛ آزمون‌های قبلی حذف cookie و cache حافظه، redirect و ورود حساب B را تأیید کردند. RED تازه AUTH-03 اکنون **restore داده A به QueryClient در session دارای token دیگر** را ثابت می‌کند، نه نمایش آن در UI؛ assertion UI پس از شکست assertion cache اجرا نشد. این دو سطح شاهد نباید با هم ادغام شوند. چهار آزمون GREEN تازه، جداسازی بین tokenها و retention مجاز همان session را در Chromium/WebKit تأیید کرده‌اند.

## ۶. تحویل برای انتشار

پیش از تغییر verdict، سه شکست حل‌نشده wallet/checkout در WebKit تعیین تکلیف و ورودی fixture backend برای dynamic config فراهم شود؛ مرزهای واقعی بخش ۴ نیز باید در محیط مجاز تأیید شوند. GREEN احراز هویت/پروفایل پس از AUTH-03، تأیید موارد مسدودشده Studio در اجراهای جداگانه، آخرین build، lint عمومی، graphify و production preview محلی ۱۰/۱۰ با exit 0 در این گزارش ثبت شده‌اند؛ caveat خروجی PowerShell در اجراهای قبلی نیز حفظ شده است. در صورت اجرای مجموعه کامل مجدد، نتیجه باید جدا از اجرای تاریخی ۴۸۶ آزمون ثبت شود. بازبینی مستقل تازه diff هفت فایل محصول، بدون تغییر فایل یا اجرای مرورگر، regression معناداری پیدا نکرد؛ این نتیجه محدود به مرور تغییرات است و همراه PASSهای محلی جایگزین تأیید مرزهای واقعی بخش ۴ نیست.

پیکربندی تولید باید مقادیر واقعی و سازگار `VITE_PERPIX_API_URL`، `VITE_PERPIX_APP_URL`، `VITE_OBJECT_STORAGE_PUBLIC_ENDPOINT`، `VITE_APP_FONT_BASE_URL`، `VITE_APP_TELEGRAM_SUPPORT`، `VITE_APP_SENTRY_DSN` و `VITE_APP_PERPIX_TAX_PERCENT` را در زمان build فراهم کند. مقدار DSN نباید در گزارش یا لاگ عمومی افشا شود؛ ارسال رویداد Sentry باید در محیط مجاز بررسی شود. مقادیر استفاده‌شده برای آزمون محلی/mock تأیید پیکربندی production نیستند.

بررسی دستی محیط مجاز staging/backend باید مسیر ورود تا خروج و انقضای session، reload همان حساب و تعویض حساب بدون restore داده قبلی، ذخیره پروفایل، upload و generation مجاز، گالری و دانلود فایل واقعی، بازگشت از پرداخت و صحت wallet سمت سرور، editor، route refresh با asset قدیمی و دسترسی مسیرهای اصلی در موبایل/RTL را پوشش دهد. CORS، signed URL و دانلود object storage، دریافت رویداد Sentry و چرخه نصب/update/offline مربوط به PWA نیز باید با پیکربندی همان محیط تأیید شوند. عملیات مالی یا مصرف اعتبار واقعی نیازمند محیط و حساب مجاز همان بررسی است.
