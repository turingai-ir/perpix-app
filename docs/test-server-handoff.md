# تحویل نسخه فعلی برای تست روی سرور

این بسته، snapshot سورس فعلی همراه با اصلاحات commit‌نشده و تست‌هاست. همه قابلیت‌های برنامه از جمله کیف پول و پرداخت در آن حفظ شده‌اند. هدف، تست واقعی تیم از داخل ایران روی سرور است. هیچ mock، محدودیت آزمایشی یا غیرفعال‌سازی پرداخت به برنامه اضافه نشده است.

## محتوای بسته

- سورس، فایل‌های public، lockfile و تنظیمات Docker/Nginx.
- تست‌های فعلی و گزارش `docs/release-readiness-2026-10-17.md`.
- نمونه تنظیمات `deploy/test.env.example` و مشخصات snapshot در `release-manifest.json`.
- فایل‌های محیطی شخصی، اطلاعات محلی، وابستگی‌های نصب‌شده و خروجی بیلد داخل بسته نیستند. بیلد روی سرور با آدرس‌های همان محیط انجام می‌شود.

## اجرای سرور

پیش‌نیاز: Docker با Compose v2، دسترسی دریافت imageها و packageها، بک‌اند و فضای ذخیره‌سازی قابل دسترس، و reverse proxy متصل به شبکه Docker به نام `perpix`.

بسته را در یک پوشه مستقل باز کنید. از همان پوشه:

```sh
cp deploy/test.env.example deploy/test.env
```

در `deploy/test.env` آدرس واقعی API، دامنه اپ و فضای ذخیره‌سازی را وارد کنید؛ تنظیمات پشتیبانی، Sentry و مالیات را مطابق محیط موجود قرار دهید. مسیر پایه API باید دقیقاً مطابق تنظیم بک‌اند باشد. مقدارهای `VITE_*` در مرورگر قابل مشاهده‌اند؛ کلید خصوصی یا رمز سرور در آن‌ها قرار ندهید.

اگر شبکه `perpix` از قبل وجود ندارد، یک بار بسازید:

```sh
docker network create perpix
```

سپس:

```sh
docker compose --env-file deploy/test.env config --quiet
docker compose --env-file deploy/test.env up -d --build test-perpix-app
docker compose --env-file deploy/test.env ps
docker compose --env-file deploy/test.env exec -T test-perpix-app wget -qO- http://127.0.0.1:8081/healthz
```

خروجی آخر باید `ok` باشد؛ این فقط سلامت وب‌سرور را نشان می‌دهد. reverse proxy باید دامنه HTTPS اپ را به `test-perpix-app:8081` در شبکه `perpix` وصل کند. Compose فعلی پورت عمومی روی میزبان باز نمی‌کند. Nginx داخلی API را proxy نمی‌کند؛ مرورگر مستقیماً به `VITE_PERPIX_API_URL` متصل می‌شود. دامنه اپ باید در تنظیمات CORS بک‌اند و فضای ذخیره‌سازی مجاز باشد. تنظیم دامنه بازگشت پرداخت نیز باید در بک‌اند/درگاه با همین محیط سازگار باشد.

بعد از تغییر مقدارهای `VITE_*`، دستور `up -d --build` را دوباره اجرا کنید؛ restart به‌تنهایی مقدارهای بیلد را تغییر نمی‌دهد. پیش از جایگزین‌کردن محیط موجود، image و تنظیمات قبلی را برای بازگشت نگه دارید.

## تست همکاران از داخل ایران

تست‌ها از مرورگر واقعی روی دامنه سرور انجام شوند؛ نصب Playwright روی سرور برای این مرحله لازم نیست. مجموعه خودکار فعلی عمدتاً دارای mock است و جایگزین تست زنده نیست.

1. ورود با حساب موجود، ثبت‌نام/کد تأیید، رمز و بازیابی رمز؛ خروج و ورود با حساب دوم روی همان مرورگر برای کنترل جدایی اطلاعات حساب‌ها.
2. ویرایش پروفایل و بررسی ماندگاری پس از refresh و ورود دوباره.
3. آپلود مرجع، تولید تصویر و ویدئو، نمایش نتیجه، گالری و دانلود؛ بررسی خطا و تلاش مجدد.
4. بازکردن تصویر در ویرایشگر، خروجی گرفتن و بررسی نمایش روی موبایل و دسکتاپ.
5. کیف پول و خرید اعتبار: ثبت مانده قبل از خرید، رفتن به درگاه، بازگشت موفق، لغو، بازگشت ناموفق، refresh صفحه نتیجه و تطبیق مانده و تاریخچه با بک‌اند. تکرار نمایش نتیجه نباید تراکنش تکراری بسازد. مبلغ و درگاه را مسئول محیط تعیین کند؛ برنامه از تنظیمات همان بک‌اند استفاده می‌کند.
6. تکرار مسیرهای اصلی در Chrome و Safari در دسترس تیم، و بازکردن مستقیم آدرس صفحات داخلی.

برای هر ایراد، دامنه، زمان با منطقه زمانی، مرورگر/دستگاه، مراحل بازتولید، نتیجه مورد انتظار و واقعی، تصویر و شناسه درخواست/تراکنش مرتبط را ثبت کنید. رمز، توکن ورود و اطلاعات کارت را در گزارش قرار ندهید.

## وضعیت اعتبارسنجی پیش از تحویل

بیلد برنامه و lint در بررسی قبلی موفق بودند؛ lint دارای هشدارهای موجود است. ۱۰ تست production preview در Chrome و WebKit موفق بودند. کل مجموعه تست‌ها سبز اعلام نشده است: سه تست مالی WebKit نتیجه قطعی ندارند و دو تست به fixture خارجی بک‌اند وابسته‌اند. جزئیات در گزارش آمادگی نسخه آمده است. پرداخت واقعی، اتصال کامل به سرویس‌ها و اجرای Docker هنوز در این محیط تأیید نشده‌اند و بخشی از تست همین سرور هستند.

این تحویل ادعای تأیید انتشار عمومی ندارد؛ قابلیت‌ها برای بررسی تیم روی سرور حفظ شده‌اند.
